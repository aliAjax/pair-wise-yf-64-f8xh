# 国际会议同声传译和发言队列控制

源提示词摘要：主持人维护代表发言队列、剩余时间、议题和临时插话；翻译团队维护多语种频道、术语和译员交接；字幕人员修正实时文本。队列调整保留版本，发言者切换后旧译文不会误绑定，并提供低延迟大屏模式和多会议厅隔离。

## 技术栈

Qwik City、TypeScript、Qwik UI、Qwik stores、TanStack Query、Modular Forms、Zod、qwik-speak。

## 本地运行

```bash
npm install
npm run dev
```

开发端口：`62029`

## 可用流程

- 多会议厅独立维护代表、议题和发言队列，切换厅时数据互不影响。
- 发言人从排队、发言中、完成到跳过，支持临时插话和剩余时间调整。
- 多语种频道维护译员、术语和交接；交接后新增字幕归属新译员。
- 实时字幕支持版本化修正，低延迟模式只保留关键状态并停用非必要动态。
- 数据保存在浏览器 localStorage，刷新后继续保留。

## 主备大屏修订序号跟播

每厅一条 append-only 权威修订流（厅内 `seq` 投递序号 + 每条字幕的 `revision` 修订序号），主、备两块屏各自维护游标、待播队列、已播记录和对账差异：

- **重连补齐**：断网期间修订攒在厅内，恢复后按 `seq` 一次性补齐并进入 catch-up；补播没走完前，新到直播修订排在补齐修订后面。
- **去重与作废**：同 `(captionId, revision)` 只播一次（重复推送在对账差异里记 dup）；比本地已播游标小的修订作废并记 stale。
- **暂停只管本屏**：主持人暂停仅作用于本屏本厅，期间攒下的留在待播队列，恢复后从暂停点接着按序播。
- **两屏对账**：两块屏跟同一厅播完后以权威流为准互相核对，漏播补入待播、旧修订记作废，游标补齐到一致。
- **改稿失效**：译员更新已播字幕版本后，对应已播游标标记失效，新版补播后恢复有效。
- **旧数据升级**：没有游标存档时按已保存的最新版本起步，历史修订不重播。

核心逻辑在 `src/screens/engine.ts`（框架无关纯函数），浏览器模拟在 `src/screens/simulation.ts`。
